# 同晓 · 答辩 PPT 大纲（12 页）

## P1 封面
标题：同晓 —— 懂中国调休的智能闹钟
副标题：Android 课程设计 · Java + MVVM
一句话卖点：**法定假不吵你，补班日不误你；叫不醒自己，组员帮你把关。**

## P2 痛点调研（用数字说话，不要泛泛而谈）
- 2026 年：33 天法定假日、**6 天调休补班**（其中 4 天落在周末）
- 原生闹钟只认"星期几" → 假日照响、补班漏响，每年至少手动改 6 次
- 宿舍场景：别人的奇怪闹钟吵醒全寝；组员不在时没人兜底叫醒
- 现有 App 要么只管"响"，要么依赖账号/服务器

## P3 差异化定位
三条主线：**日历智能**（调休）+ **行为科学**（挑战/自适应）+ **协作**（局域网互助）
边界明确：不做睡眠周期、不做云端、不做 ML（写在展望，避免被追问）

## P4 系统架构（一页讲清分层）
UI(Fragment/Activity) → ViewModel/LiveData → 引擎(节假日/触发/挑战/自适应/天气) → 数据(Room 6 表 + Prefs) → 系统能力(AlarmManager/前台服务/BroadcastReceiver/NSD/TCP)
强调：**零第三方框架**（无 Hilt/RxJava/图表库），全部原生 Java 实现

## P5 调休引擎（核心创新点）
- 数据源：国务院办公厅公告（国办发明电〔2025〕7号），assets 内置 JSON
- 判定优先级：**补班日 > 法定假 > 星期几**
- 演示：`HolidayResolverTest` 覆盖公告里 7 个假日段 + 6 个补班日；`2026-01-04(周日) 必须响`
- 降级：数据缺失/JSON 损坏 → 普通星期 + UI 黄条（"宁响勿哑"）

## P6 拖不死的响铃链路
- `setAlarmClock`（Doze 白名单级）→ 前台服务（`mediaPlayback` 类型）→ 全屏停铃页（锁屏盖屏）
- 三道保险：响铃前预排下一次 / 开机与改时全量重排 / 6h 自检补排
- 三个"必须闭环"的入口：通知"停止"action、返回键等价停铃、闹钟行被删也先停声
- 现场可答：为什么不是 `setExact`？为什么后台拉起页面失败？（Android 10+ 限制 → 全屏 intent）

## P7 停铃挑战（演示爆点）
- 离线算术题生成器 + 30 题题库；题数 1–5、题型可选、答错策略三种
- 安全阀：长按紧急停止（固定可见，任何字号都不出屏），记 `EMERGENCY_STOP`（自适应可区分"真起床"与"逃生"）
- 防恶搞：来自组员的配置一律 `clamped()`（题数/延迟/摇动次数硬上限）

## P8 局域网互助（第二个演示爆点）
- NSD 发现同 Wi-Fi 组员 → TCP 长连接（换行 JSON）→ 心跳/离线判定/退避重连
- 权限模型（重点讲）：**绑定时一次性授权**，权限位 = 静音/可见时刻表/可发起代设
- 两条语义分界：**正在响的闹钟 → 直接静音（免确认）**；**设置类（改题目/代设）→ 发申请，本人同意才生效**
- 安全：接收端不信任发起端（越权拒绝 + 参数钳制 + 操作留痕）

## P9 智能增强
- 自适应：14 天窗口 → 停铃时刻中位数 → 连续 5 天偏晚则建议改时间（**只建议不自动改**）
- 天气：Open-Meteo → 缓存 24h → 恶劣才提前；过期/失败一律不提前
- 统计：自绘折线（起床趋势）+ 贪睡榜 + 被静音榜

## P10 工程化与质量（老师最爱看的部分）
- 26 步执行计划 + **每步 5 道关卡**（构建含 lint / 单元测试 / 范围自查 / **独立评审** / 运行验证）
- 独立评审真实抓出的问题（挑 3 个讲）：
  1. 镜像表主键用自增 id → 对端重装后会**静音错闹钟**（改为 uid + 唯一索引）
  2. 删除闹钟接受 id=0 → 静默删掉别人的事件（加前置校验）
  3. 停铃页返回键没停服务 → **铃声无法停止**（通知加停止 action + 返回键停铃）
- 测试：330+ instrumentation 用例；断言下沉到系统状态（`getNextAlarmClock`/`getActiveNotifications`/`FLAG_NO_CREATE`）

## P11 演示脚本（现场 3 分钟）
1. 列表页副标题"明天是调休补班日" → 新建 07:30 智能工作日闹钟
2. 打开"停铃挑战" → 把时间设成 1 分钟后 → 锁屏等响 → 全屏页答题 → 停铃
3. 设置页：城市保存反馈、节假日数据状态
4. 双机演示：A 手机看到 B 的"06:40 背单词"正在响 → 一键静音 → B 手机停声、双方操作留痕
5. 收尾：`adb shell content query --uri content://com.course.tongxiao.alarms` 展示只读共享

## P12 展望与限制
- 展望：端侧 ML 起床预测、睡眠周期、云端多设备同步、手表联动、一次性闹钟顺延
- 限制（主动交代，显得诚实）：全屏页锁屏限制、厂商 ROM 需加白、局域网互助需同网、节假日数据需年度更新

## 答辩可能被问的 5 个问题（准备答案）
1. 调休数据怎么保证正确/可更新？→ 公告溯源字段 + 逐日单测 + 设置页导入 + 缺失降级
2. 为什么用前台服务而不是普通服务？→ 后台限制与锁屏响铃可靠性
3. 互助为什么不做逐次确认？→ 凌晨扰民场景本人不可能在线确认；设置类仍要求确认
4. 电量/性能怎么考虑？→ 不做轮询，靠 AlarmManager 精确唤醒 + 6h 自检
5. 测试怎么证明"真的会响"？→ 系统状态断言 + 模拟器/真机实跑 + 测试报告
