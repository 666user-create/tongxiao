# 同晓 · 演示脚本（现场 5 分钟）

> 演示前 10 分钟检查清单，然后按 A→E 顺序走。每段都给了「失败降级路径」，答辩时卡住不慌。

## 0. 演示前检查（务必做）

| 项 | 命令/操作 | 通过标准 |
|---|---|---|
| 两台设备同一 Wi-Fi | 手机 A/B 连同一个热点（或 A 开热点、B 连 A） | 两台能互相 ping 通（可用文件互传验证） |
| 安装 | `adb install -r dist\tongxiao-release.apk`（两台都装） | 桌面出现"同晓" |
| 通知权限 | 首次启动弹窗 → 允许 | 后续响铃能看到通知 |
| 精确闹钟 | 设置→应用→同晓→闹钟和提醒 → 允许 | 否则响铃可能延迟 |
| 电池优化 | 关掉"同晓"的省电限制 / 允许自启动 | 熄屏后仍能响（国产 ROM 必须做） |
| 预置数据 | A 机建 2~3 个闹钟（含 1 个开了"停铃挑战"） | 列表有内容，演示不空 |
| 演示组码 | A 机宿舍页"创建宿舍组"，记下 6 位码 | 页面显示组码与"我：昵称" |

> 建议额外准备：**提前一晚**让两台设备各响过一次闹钟，这样统计页有折线、自适应卡片有样本（否则显示"继续记录中"）。

## A. 调休引擎（60 秒）—— 讲"为什么不是普通闹钟"

1. 打开同晓 → 闹钟 tab
2. 指列表顶部副标题：「**明天是调休补班日**」/「**明天是法定假日**」
3. 新建一个闹钟 → 重复方式选「**智能工作日（法定假跳过，补班照常）**」→ 保存
4. Toast 会显示「**已保存，下次响铃：明天 07:30**」

**话术**：
> 原生闹钟只认星期几。2026 年有 33 天法定假日和 6 天调休补班，其中 4 个补班日落在周末。同晓的做法是：补班日优先级最高（照响），其次是法定假日（跳过），最后才是星期几。数据来自国务院办公厅公告，内置在 assets 里，缺失年份自动降级为普通星期并在设置页给黄条提示——**宁响勿哑**。

**降级**：若副标题显示"节假日数据尚未更新"，直接讲降级策略（这是加分项，不是缺陷）。

## B. 停铃挑战 + 响铃链路（90 秒）—— 主演示

1. 编辑刚才的闹钟 → 打开「**停铃挑战**」开关
2. 点「**试响（10 秒后响铃）**」→ 立刻按电源键锁屏
3. 等到响铃 → **全屏停铃页自己盖在锁屏上** → 答 2 道题 → 停铃
4. 再演示一次，这次**长按底部「紧急停止」3 秒**

**话术**：
> 响铃用 `setAlarmClock`（Doze 白名单级）+ 前台服务，所以熄屏能响。全屏页只在锁屏/熄屏时由系统拉起——Android 10+ 禁止后台直接 startActivity，亮屏解锁时走环形通知带"停止"按钮，这是平台规范。挑战默认关闭，是用户显式开启的；紧急停止永远可用，且会被记成 `EMERGENCY_STOP`，这样"真起床"和"逃生"能区分开，自适应才不会学坏。

**降级**：若锁屏没弹全屏页 → 解锁点通知进停铃页，说明"这就是平台限制"。

## C. 宿舍互助（120 秒）—— 最强演示

> 两台设备并排放在桌上，投影能看到两台屏幕最好。

1. **A 机**：宿舍 tab →「创建宿舍组」→ 出现 6 位组码
2. **B 机**：宿舍 tab → 输入组码 →「加入」
3. 两台互相看到对方：昵称 + 绿点（在线）+ 权限 chips（静音 / 可见时刻表）
4. **A 机**触发一个正在响的闹钟（提前用"试响"预约 30 秒后，或直接响）
5. **B 机**在宿舍页看到「A 的 06:40 背单词 **正在响**」→ 点「**静音**」
6. **A 机铃声立刻停止**，A 机的统计页「被静音」计数 +1，A 的闹钟事件留痕 `remote:<B的设备号>`

**话术（这是评分重点）**：
> 两条语义分界：「正在响的闹钟」**免确认直接静音**——因为凌晨三点吵醒全寝时，被吵的人不可能先发申请等本人同意；而「改设置类」（改题目、代设闹钟）**必须本人同意才生效**，落在待确认列表里。
>
> 安全上**接收端不信任发起端**：所有越权指令返回拒绝码（`PERMISSION_DENIED`），参数一律钳制（题数 ≤5、延迟 ≤30s、标签 ≤40 字）。总闸一关，所有远程指令全部拒绝，且不需要清除已授权项。
>
> 协议是 NSD 发现 + TCP 长连接 + 换行 JSON，心跳 60 秒；没有服务器、没有账号，退组时三张表在一个事务里清理干净。

**降级**：
- 找不到对方 → 退组重进（每次进前台会重新注册 NSD）；或直接讲"发现走 mDNS，模拟器上我用 127.0.0.1 回环覆盖了协议与权限的 78 个测试"
- 想演示代设 → A 机发 SET_REQUEST，B 机待确认列表点"同意"，A 的闹钟真的多一个

## D. 智能增强（60 秒）

1. **编辑页**：指向「行为建议」卡（"最近 5 天你都在 07:52 左右才停铃，建议改到 07:50"）→ 点「采纳」→ 时间变了，但仍需点保存
2. **天气**：设置 tab →「选择地区（省 / 市 / 区县）」→ 三个滚轮选到「浙江省 杭州市 西湖区」→ 确定（页面立即显示"已选择：浙江省 杭州市 西湖区"）→ 回编辑页看「明天天气不佳，明早提前 10 分钟响铃」
3. **统计 tab**：折线（起床趋势）+ 贪睡榜 + 被静音榜

**话术**：
> 自适应**只建议不自动改**——闹钟时间是最敏感的设置，自动改会让人错过面试。算法是 14 天窗口取停铃时刻中位数，连续 5 天偏晚才建议；跨零点的场景（23:55 闹钟、00:15 才停）单独处理，朴素减法会算成负 23 小时。
>
> 天气联动有个设计坑：提前量**必须放在注册时刻**（AlarmScheduler），不能放在接收器——接收器是"已经到点"才跑，物理上不可能提前。而且内置"提前后如果落到过去就放弃提前"，否则会立刻响。

## E. 工程质量（60 秒）—— 让老师看到不是"能跑 demo"

1. 打开 `docs/test-report.md`：**243 个 instrumentation 测试全绿**
2. 打开 `docs/design.md`：26 步计划 + 每步五道关卡（构建含 lint / 测试 / 范围自查 / 独立评审 / 运行验证）
3. 讲评审抓出的真实缺陷（挑 3 个，见 test-report §5）
4. 命令行演示只读共享：
```bat
adb shell content query --uri content://com.course.tongxiao.alarms/alarms --projection id:label:hour:minute
adb shell content insert --uri content://com.course.tongxiao.alarms/alarms --bind label:s:x
```
第一条返回闹钟列表，第二条报 `UnsupportedOperationException: AlarmProvider is read-only`

**话术**：
> 每个里程碑都用**无上下文的独立评审代理**只看 diff 和设计文档复审，抓出过"镜像表主键用自增 id 会静音错闹钟""停铃页返回键导致铃声无法停止"这类真问题。测试断言下沉到系统状态——不是"方法被调用过"，而是"AlarmManager 真的记住了""通知真的存在"。

## 备用：被问住的常见问题（速查）

| 问题 | 一句话回答 |
|---|---|
| 为什么不用 Kotlin/Hilt？ | 课程要求 Java + 经典 MVVM；手工注入只有一个网关和一个 DB 单例，加框架反而增加答辩解释成本 |
| 后台被杀怎么办？ | 6h WorkManager 自检对比 Room 期望与实际注册，缺了补排；再加厂商白名单引导 |
| 互助要不要服务器？ | 不要，纯局域网 NSD+TCP，零成本、零账号、不碰隐私 |
| 数据安全？ | 组码 + 同网限制；接收端钳制与权限位；只读 Provider 拒绝一切写 |
| 没做的功能？ | 端侧 ML 起床预测、睡眠周期、云端同步、手表联动——写在展望里，主动交代 |
